# Additionally, as of 2026-08-06 several defects were fixed that change scores
# for all future runs:
#   - sim/rollout_core.py: scored e_y/e_psi and the off-track check aliased
#     the PLANNER-relative error whenever SLAM noise was off (the default),
#     so ~60% of the score measured controller-vs-planner agreement with no
#     ground-truth anchor
#   - sim/speed_profile.py: compute_speed_profile() had no longitudinal
#     propagation, so it could demand ~273 m/s^2 of braking that speed_rmse
#     then punished the controller for not achieving; it also used its own
#     copy of the curvature heuristic with different defaults from the live
#     node (scan_end 14 vs 24 m, a_lat_max 5.886 vs 4.0, v_max 20 vs 15),
#     commanding 2.45 m/s faster on average than the car will ever drive.
#     Pass 0 now delegates to curvature_speed() so the two cannot diverge.
#   - settings.py + sim/scoring.py: METRIC_SCALES added. Metrics are now
#     normalised by a reference magnitude BEFORE weighting. Previously a
#     metric's influence was weight x typical magnitude, which made the score
#     effectively single-objective: comparing a deliberately-hunting gain set
#     against a neutral baseline, rmse + peak_lateral_error accounted for the
#     entire -0.2605 difference while all ten other metrics combined
#     contributed +0.0064. steering_reversal_rms had an effective
#     contribution of 0.0003 despite a nominal weight of 0.05.
#   - tuner/offline_tuner.py: task aggregation changed from
#     0.7*mean + 0.3*max to 0.7*mean + 0.3*quantile(TAIL_QUANTILE=0.8).
#     With a flat +3.0 DNF penalty, the hard max let ONE unlucky task in ten
#     shift the objective by ~0.9 — a plausible gain set scored 3rd-worst of
#     six purely because one of its ten tasks DNF'd.
#
# BECAUSE OF THE ABOVE, scores are not comparable across the 2026-08-06
# boundary either. The scale changed: normalisation means a run with every
# metric at its reference magnitude scores 1.0 before bonuses, where
# previously the raw weighted sum was much smaller. Expect post-fix scores to
# be numerically LARGER (less negative) than pre-fix ones for the same
# driving quality. That is a change of units, not a regression.
#
# For future entries: record planner mode (USE_PLANNER), the scoring-function
# version/hash, and the tuner configuration alongside the gains. The commit
